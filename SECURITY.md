# Security Policy

## Supported versions

OSIEL Labs projects are at different stages of development. Supported versions, release channels and security-update commitments must be defined in each individual repository. **No general production support or response-time commitment is currently declared at the organization level.**

## Reporting vulnerabilities

Please **do not open public issues** containing vulnerability details, credentials, private data, exploit instructions or proofs of concept.

For repositories with GitHub's **Private Vulnerability Reporting** enabled, use the repository's **Security → Report a vulnerability** option.

If private reporting is not available, contact repository maintainers through an explicitly published private channel. If no private channel is listed, do not post the vulnerability publicly; request a secure reporting route without sharing sensitive details.

Include the affected component and version, impact, reproducibility details and any suggested mitigation once a secure channel is available.

## Disclosure

Please coordinate disclosure with the maintainers and avoid exposing users or systems to unnecessary risk. Repository-specific policies take precedence over this general guidance.
