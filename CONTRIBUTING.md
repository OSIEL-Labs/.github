# Contributing to OSIEL Labs projects

Thank you for your interest in OSIEL Labs.

## Before contributing

1. Read the target repository's README, license, roadmap, and contribution instructions.
2. Confirm that the project currently accepts external contributions.
3. For substantial changes, open a discussion or issue first when that feature is enabled.
4. Keep each proposal focused and provide a clear rationale.

## Engineering expectations

- Describe the user or technical problem, expected behavior and scope.
- Include reproducible steps for bug reports.
- Update applicable tests, documentation and migration notes when changing behavior.
- Explain security, backward compatibility, performance and data integrity implications.
- Avoid unrelated refactors in the same change.
- Do not commit credentials, personal data, customer records or private research materials.

## Pull request process

When pull requests are enabled, use the provided template. Reviews may request changes; acceptance depends on project readiness, maintainer availability, and repository-specific policies.

## Intellectual property and licensing

**No blanket permission is granted to use, modify or redistribute code across OSIEL Labs repositories.** Consult the license of each individual repository. If none is present, do not assume an open-source license.

For sensitive vulnerabilities, follow `SECURITY.md` and do not disclose exploit details in public issues.
