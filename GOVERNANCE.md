# Organization governance — OSIEL Labs

## Purpose

Provide a consistent baseline for organizing, reviewing and maintaining OSIEL Labs software projects.

## Repository lifecycle

Projects may move through **research**, **prototype**, **active development**, **release candidate**, **maintained** and **archived** stages. Maintainers should identify the current status in each repository.

## Ownership and decisions

Repository maintainers are responsible for prioritizing issues, reviewing proposals, protecting releases and documenting important technical decisions. Major architectural choices should include rationale, alternatives, risks and validation criteria, preferably through ADRs or an equivalent project-specific record.

## Reviews and change control

Where appropriate, protect default branches, use pull requests, require status checks and ensure changes affecting security, data integrity or compatibility receive explicit review. Apply least-privilege access and avoid committing credentials or sensitive research.

## Release practices

A project should not be described as production-ready without defined release, test, documentation and support expectations. Public release notes should distinguish implemented capabilities from plans.

## Policy precedence

Project-specific governance, contribution, license and security documents take precedence over these shared defaults.
